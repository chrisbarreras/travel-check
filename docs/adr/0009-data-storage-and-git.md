# ADR-0009: Raw data stays out of git; small derived data is committed

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

Raw BTS data is millions of rows per year, far too large for git. The static Phase 1 site needs its derived JSON available at deploy time, and running the full pipeline during every deploy would be slow and fragile.

## Decision

- Raw downloads go in `data/raw/`, which git ignores.
- The pipeline is **reproducible**: the data period and sources are pinned in configuration, so anyone can download and rebuild.
- The **small derived files the site needs are committed**, so static deploys require no pipeline run.
- Size budget for derived site data: about **1–2 MB compressed** in total. Exceeding it means revisiting [ADR-0006](0006-risk-as-slack-distributions.md) (for example, storing quantiles) or reducing route coverage.

## Consequences

- Clones stay small, and deploys are simple and fast.
- Committed derived data can fall out of date with the pipeline code; rebuilding and committing it is a deliberate step, and CI can check that it was generated by the current pipeline version.
- Reviewers can inspect the exact data behind the live site.
